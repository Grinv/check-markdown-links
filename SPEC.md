# SPEC: checkmdlinks — CLI-проверка ссылок в Markdown

Спецификация для генерации приложения агентом. Читается моделью: тезисно, без
пояснений «зачем». Все решения ниже — контракт, а не рекомендация. Если пункт
не описан — выбрать простейшую реализацию и не расширять объём.

## 1. Цель

- Вход: путь к папке проекта.
- Найти все Markdown-файлы, извлечь из них ссылки, проверить каждую.
- Локальная ссылка — проверка существования файла/каталога на диске.
- Внешняя (`http`/`https`) — проверка доступности HTTP-запросом.
- Выход: цветной табличный отчёт в консоль + код выхода для CI.

## 2. Жёсткие ограничения

- **Node.js 24.19.0 LTS** («Krypton»). Целевая версия зафиксирована в
  `package.json` (`engines`) и в `.nvmrc`.
- **Ноль внешних зависимостей.** `dependencies` и `devDependencies` пустые.
  `npm install` не должен ничего скачивать. Запрещены `chalk`, `kleur`,
  `glob`, `node-fetch`, `commander`, `yargs`, тест-раннеры (jest/vitest/mocha),
  сборщики, транспайлеры, линтеры-как-зависимости.
- Разрешено только встроенное:
  - `node:fs/promises`, `node:fs` (для `createReadStream` при необходимости),
  - `node:path`, `node:url` (`fileURLToPath`, `pathToFileURL`),
  - `node:util` → `parseArgs` (парсинг аргументов),
  - глобальный `fetch` + `AbortSignal.timeout` (undici внутри Node),
  - `node:test`, `node:assert/strict` (тесты),
  - `node:http` — **только в тестах**, как локальный мок-сервер,
  - `node:os` (например, `os.cpus()` — не обязательно).
- ESM (`"type": "module"`), `import`, без CommonJS и без TypeScript.
- Цвета — вручную ANSI-escape-последовательностями.
- Никаких сетевых обращений в тестах.

## 3. CLI-контракт

Основная форма запуска:

```
checkmdlinks <folder>
```

Эквивалентные способы: `node bin/checkmdlinks.js <folder>`,
`npm link` → `checkmdlinks <folder>`, `npx checkmdlinks <folder>`.

- `<folder>` — позиционный аргумент, обязателен, ровно один.
  Относительный путь разрешается от `process.cwd()`.
- Если аргумент не передан — печать usage в `stderr`, exit `2`.
- Если путь не существует или не каталог — ошибка в `stderr`, exit `2`.

Флаги (все опциональны, `parseArgs`):

| Флаг | Тип | Дефолт | Смысл |
|---|---|---|---|
| `--timeout <ms>` | number | `5000` | Таймаут одного HTTP-запроса |
| `--concurrency <n>` | number | `8` | Одновременных HTTP-запросов |
| `--no-external` | boolean | `false` | Не проверять `http(s)`, помечать `skipped` |
| `--only-external` | boolean | `false` | Не проверять локальные ссылки |
| `--ignore <name>` | string, многократно | — | Доп. каталог/имя для исключения при обходе |
| `--json` | boolean | `false` | Машинный вывод вместо таблицы |
| `--no-color` | boolean | `false` | Отключить ANSI |
| `-h`, `--help` | boolean | — | Usage в `stdout`, exit `0` |
| `-v`, `--version` | boolean | — | Версия из `package.json`, exit `0` |

- Нераспознанный флаг → сообщение + usage в `stderr`, exit `2`.
- Нечисловое/отрицательное значение `--timeout`/`--concurrency` → exit `2`.
- `--timeout` и `--concurrency` парсятся как строки (`parseArgs` не умеет
  number) и валидируются вручную.

Коды выхода:

- `0` — сломанных ссылок нет (warning-и не влияют).
- `1` — есть хотя бы одна сломанная ссылка.
- `2` — ошибка использования: нет аргумента, плохой флаг, папки не существует.

Цвета отключаются, если: `--no-color`, либо переменная окружения `NO_COLOR`
непустая, либо `!process.stdout.isTTY`, либо `--json`.

## 6. Обход папки (`src/scan.js`)

- `scanMarkdownFiles(rootDir, { ignore }) -> Promise<string[]>` (абсолютные пути,
  отсортированы для детерминизма).
- Рекурсия через `fs.readdir(dir, { withFileTypes: true })`.
- Целевые расширения: `.md`, `.markdown` (регистр имени игнорировать).
- Игнорируемые каталоги по умолчанию: `node_modules`, `.git`, `dist`, `build`,
  `coverage`, `.next`, `.cache`, `vendor`. Плюс всё из `--ignore`.
- Прочие скрытые каталоги (имя с `.`) — пропускать; скрытые `.md`-файлы —
  проверять.
- Симлинки на каталоги **не** обходить (защита от циклов). Симлинки на файлы —
  обрабатывать как файлы.
- `EACCES`/`EPERM` при чтении каталога → warning в отчёт, обход продолжается.
- Ошибка чтения конкретного файла → warning, файл пропускается, процесс не
  падает.

## 7. Извлечение ссылок (`src/extract.js`)

- `extractLinks(content, filePath) -> Link[]`, где
  `Link = { file, line, column, text, rawUrl, kind }`;
  `kind ∈ { inline, image, reference, autolink, bare }`.
- `line` и `column` — 1-based, указывают на начало ссылки.
- Парсер построчный и намеренно упрощённый (не CommonMark).

Что распознаём:

- inline: `[текст](url)`, изображения `![alt](url)`;
- с title: `[t](url "title")`, `[t](url 'title')`, `[t](url (title))` — title
  отбрасывается;
- угловые скобки в назначении: `[t](<url with spaces>)` — скобки снимаются;
- reference-стиль: использование `[текст][id]`, `[текст][]`, и определения
  `[id]: url "title"` в начале строки (допускается до 3 пробелов отступа).
  Проверяется **url из определения**; использование без определения →
  broken-категория `UNDEFINED_REFERENCE`;
- автолинки: `<https://example.com>`, `<http://…>`;
- «сырые» `file:///…` вне скобок — распознавать как `bare`.

Что не распознаём (сознательно, вне объёма): HTML `<a href>`, `<img src>`,
ссылки, разорванные переносом строки внутри `(...)`.

Правила исключения:

- Содержимое fenced-блоков: открывающий маркер ``` или ~~~ (3+ символа,
  отступ ≤ 3 пробелов); закрывается маркером того же символа длиной не меньше
  открывающего; незакрытый блок тянется до конца файла.
- Содержимое inline-кода: парные обратные кавычки в строке, включая
  многосимвольные ограничители (`` ``текст`` ``).
- Экранированные скобки `\[`, `\]`, `\(`, `\)` не образуют ссылку.
- Балансировка круглых скобок внутри `(...)`: вложенные пары допустимы
  (`[t](a(b)c.md)`), незакрытая скобка → ссылка не распознана.

## 8. Классификация и разрешение путей (`src/resolve.js`)

`classify(rawUrl, { sourceFile, rootDir }) -> { type, target, reason }`,
`type ∈ { external, local, skipped, invalid }`.

Порядок правил (первое совпадение выигрывает):

1. Пустой `rawUrl` или только пробелы → `invalid`, категория `EMPTY_URL`
   (считается сломанной ссылкой).
2. Начинается с `#` → `skipped`, причина `ANCHOR_ONLY` (проверка якорей вне
   объёма).
3. Схема `http:` / `https:` → `external`, `target` = URL с отброшенным
   фрагментом; query сохраняется.
4. Схема `file:` → `local`, `target` = `fileURLToPath(url)` (абсолютный путь на
   диске; фрагмент/query отбросить до преобразования).
5. Прочие схемы (`mailto:`, `tel:`, `data:`, `ftp:`, `javascript:`,
   `vscode:` и любые `^[a-zA-Z][a-zA-Z0-9+.-]*:`) → `skipped`, причина
   `UNSUPPORTED_SCHEME`.
6. Протокол-относительная `//host/path` → `external`, подставить `https:`.
7. Начинается с `/` → `local`, **разрешается относительно `rootDir`**
   (корня сканирования), а не относительно `/` файловой системы и не
   относительно каталога файла: `path.join(rootDir, urlPath)`.
8. Иначе → `local`, **относительно каталога файла-источника**:
   `path.resolve(path.dirname(sourceFile), urlPath)`.
   Не использовать `process.cwd()` и не использовать `rootDir`.

Нормализация локального пути перед проверкой (в этом порядке):

1. Отрезать фрагмент: всё от первого `#`.
2. Отрезать query: всё от первого `?`.
3. `decodeURIComponent(...)`; при `URIError` (например, одиночный `%`) —
   использовать исходную строку без декодирования.
4. Заменить `\` на `/` (ссылки в windows-стиле), затем `path.resolve`/`join`.
5. Пустой результат после отрезания фрагмента (ссылка вида `#x` уже отсечена
   правилом 2; вида `?x=1` → путь пуст) → `invalid`, `EMPTY_URL`.

`..`, выводящие за пределы `rootDir`, разрешаются как обычные пути и
проверяются на существование (за пределы выходить можно, это не ошибка).

## 9. Проверка локальных ссылок (`src/check-local.js`)

- `checkLocal(absPath) -> { status, reason }`, `status ∈ { ok, broken }`.
- `fs.stat(absPath)`: успех → `ok` (существующий каталог тоже `ok`, причина
  `DIRECTORY`).
- `ENOENT` → `broken`, причина `NOT_FOUND`.
- Висячий симлинк: `stat` даёт `ENOENT` → `broken`, `BROKEN_SYMLINK`
  (различать через `fs.lstat`, если нужно точнее).
- `EACCES` → `broken`, `NO_ACCESS`.
- Кэшировать результат по абсолютному пути (Map) — один `stat` на путь.
- macOS/Windows FS регистронезависимы: ссылка `./README.MD` на файл `README.md`
  будет признана `ok`. Это принятое поведение; проверку регистра по `readdir`
  не реализуем и указываем ограничение в README.

## 10. Проверка HTTP (`src/check-http.js`)

- `checkHttp(url, { timeoutMs, userAgent }) -> { status, httpStatus, reason, redirects }`;
  `status ∈ { ok, broken, warning }`.
- Стратегия запросов:
  1. `HEAD` с `redirect: "follow"`.
  2. Если ответ `405`, `501`, `403` или `404` — повторить `GET` с заголовком
     `Range: bytes=0-0` (часть серверов не поддерживает HEAD). Итоговый вердикт
     берётся из `GET`.
  3. Тело ответа всегда сбрасывать (`res.body?.cancel()`), чтобы не течь.
- Таймаут: `signal: AbortSignal.timeout(timeoutMs)`, дефолт 5000 мс. Таймаут
  покрывает весь запрос, включая редиректы. Прерывание → `broken`, причина
  `TIMEOUT` (в `fetch` это `AbortError` / `TimeoutError`).
- Заголовки: `User-Agent: checkmdlinks/<version>`, `Accept: */*`.
- Классификация ответа:
  - `2xx` → `ok`;
  - `3xx` (после follow, т.е. фактически не должно встречаться) → `ok`;
  - `429` → `warning`, причина `RATE_LIMITED` (не влияет на exit code);
  - `401`, `403` → `warning`, причина `FORBIDDEN` (сайты часто блокируют
    ботов; не считать сломанным);
  - остальные `4xx` → `broken`, причина `HTTP_<code>`;
  - `5xx` → `broken`, причина `HTTP_<code>`.
- Классификация сетевых ошибок (по `err.cause?.code` / `err.code`):
  - `ENOTFOUND`, `EAI_AGAIN` → `DNS`;
  - `ECONNREFUSED`, `ECONNRESET`, `EHOSTUNREACH`, `ETIMEDOUT`, `EPIPE` →
    `CONNECTION`;
  - `CERT_HAS_EXPIRED`, `UNABLE_TO_VERIFY_LEAF_SIGNATURE`, `ERR_TLS_*` → `TLS`;
  - слишком много редиректов / `ERR_TOO_MANY_REDIRECTS` → `REDIRECT_LOOP`;
  - всё прочее → `NETWORK` (текст ошибки в отчёт).
  Все они → `broken`.
- Повтор: **одна** дополнительная попытка только при `TIMEOUT` и
  `CONNECTION`/`NETWORK`; не повторять при HTTP-статусах, `DNS`, `TLS`.
  Без экспоненциального бэкоффа.
- Дедупликация: кэш `Map<normalizedUrl, Promise<result>>`. Один и тот же URL
  (после отбрасывания фрагмента) запрашивается один раз за запуск, даже если
  встречается в разных файлах.
- Параллелизм: собственный пул на `--concurrency` (дефолт 8) — очередь задач и
  N воркеров; без сторонних библиотек. Порядок результатов не важен, порядок
  вывода восстанавливается сортировкой в отчёте.

## 11. Отчёт (`src/report.js`)

Текстовый режим:

- Заголовок: сканируемая папка, число файлов, число ссылок.
- Группировка по файлу; путь файла — относительный от `rootDir`, выводится
  жирным/подчёркнутым.
- По умолчанию печатать только `broken` и `warning` строки; `ok`/`skipped`
  учитывать только в сводке.
- Колонки, выровненные по максимальной ширине в группе:
  `строка:колонка | тип | статус/причина | url`.
  - `тип` — `local` / `external`;
  - `статус` — код (`404`, `500`) либо категория (`NOT_FOUND`, `TIMEOUT`, …);
  - длинный url обрезать до 80 символов с `…`.
- Файл без проблем — не печатать.
- ANSI: `ok` зелёный (`\x1b[32m`), `broken` красный (`31`), `warning` жёлтый
  (`33`), `skipped` серый (`90`), сброс `\x1b[0m`. Заголовки — `\x1b[1m`.
  При отключённых цветах — те же строки без escape-последовательностей.
- Итоговая сводка: файлов просканировано, ссылок найдено, уникальных URL
  запрошено, `ok` / `broken` / `warning` / `skipped`, затраченное время (мс).
- Финальная строка: `OK` (зелёный) либо `N broken link(s)` (красный).

Режим `--json` (в `stdout`, единственный вывод, без цветов):

```json
{
  "root": "/abs/path",
  "scannedFiles": 12,
  "totalLinks": 87,
  "uniqueExternalUrls": 31,
  "durationMs": 1423,
  "summary": { "ok": 80, "broken": 4, "warning": 1, "skipped": 2 },
  "results": [
    {
      "file": "docs/intro.md",
      "line": 14,
      "column": 3,
      "kind": "inline",
      "text": "установка",
      "rawUrl": "./setup.md",
      "type": "local",
      "target": "/abs/path/docs/setup.md",
      "status": "broken",
      "httpStatus": null,
      "reason": "NOT_FOUND"
    }
  ],
  "warnings": ["EACCES: docs/private"]
}
```

- В `results` попадают **все** ссылки, включая `ok` и `skipped`.
- `file` — путь относительно `root`, с `/` как разделителем.
- Схема стабильна: поля не переименовывать, отсутствующие значения — `null`.
- Сортировка `results`: по `file`, затем `line`, затем `column`.

## 12. Тесты

- Раннер: `node:test`, ассерты `node:assert/strict`. Запуск `npm test`
  (`node --test`), покрытие `npm run coverage`.
- Файлы: `test/extract.test.js`, `test/resolve.test.js`,
  `test/check-local.test.js`, `test/check-http.test.js`,
  `test/scan.test.js`, `test/report.test.js`, `test/cli.test.js`.
- Фикстуры: статические — в `test/fixtures/`; временные (симлинки, каталоги с
  пробелами, права) — создавать в `fs.mkdtemp(os.tmpdir())` в `before`/`beforeEach`
  и удалять в `after` (`fs.rm(dir, { recursive: true, force: true })`).
- HTTP: локальный сервер `node:http` на порту `0` (`server.address().port`),
  поднимается в `before`, закрывается в `after`. Реальные внешние адреса
  запрещены — тесты должны проходить без сети.
- CLI-тесты: запуск через `node:child_process.spawn` (`execFile`) бинаря
  `bin/checkmdlinks.js` с временной папкой; проверять `stdout`, `stderr`,
  `code`.
- Каждый тест изолирован: без общего мутируемого состояния, кэши создавать
  внутри вызова (кэш — параметр/локальная Map, не модульная переменная,
  иначе тесты потекут друг в друга).

Обязательные edge cases:

**Пути и разрешение**
- относительная ссылка без префикса (`setup.md`) — относительно **каталога
  файла**, а не cwd: файл в `docs/a.md` со ссылкой `b.md` → `docs/b.md`;
- `./file.md`, `../file.md`, `../../out.md` (выход за пределы `rootDir` —
  проверяется, не считается ошибкой сам факт выхода);
- корневая `/docs/x.md` → относительно `rootDir`, а не `/`;
- один и тот же относительный url в файлах на разных уровнях вложенности
  разрешается в разные абсолютные пути;
- `file:///abs/path.md` — существующий и несуществующий;
- ссылка на каталог → `ok` / `DIRECTORY`;
- имя с пробелом через `%20` (`./my%20doc.md` → файл `my doc.md`);
- имя с `#` в url (`./a.md#section` → проверяется `a.md`);
- url с query (`./a.md?v=1`);
- `<./file with spaces.md>` в угловых скобках;
- url с некорректным процент-кодированием (`./100%.md`) — не падать.

**Битые ссылки**
- несуществующий файл → `broken`/`NOT_FOUND`, exit `1`;
- пустой url `[t]()` → `broken`/`EMPTY_URL`;
- висячий симлинк → `broken`;
- `[t][missing]` без определения → `broken`/`UNDEFINED_REFERENCE`.

**Парсинг**
- ссылки внутри ``` -блока и внутри `~~~`-блока не извлекаются;
- ссылка внутри inline-кода не извлекается;
- незакрытый fenced-блок «съедает» остаток файла;
- `![alt](img.png)` распознаётся как `image`;
- title в трёх формах кавычек отбрасывается;
- вложенные круглые скобки в url;
- экранированные `\[not a link\]`;
- reference-стиль: `[t][id]`, `[t][]`, определение с отступом;
- автолинк `<https://…>`;
- `line`/`column` совпадают с фактической позицией (проверить на многострочной
  фикстуре);
- две ссылки в одной строке — обе с корректными разными `column`.

**HTTP (локальный мок-сервер)**
- `200` → `ok`;
- `301` → `200` (follow, итог `ok`);
- `404` → `broken`/`HTTP_404`;
- `500` → `broken`/`HTTP_500`;
- `429` → `warning`, exit `0`;
- `403` → `warning`;
- `HEAD` → `405`, затем `GET` → `200` ⇒ `ok` (сервер отвечает по методу);
- таймаут: обработчик не отвечает дольше `--timeout` (тест с `--timeout 100`)
  → `broken`/`TIMEOUT`, тест не висит;
- обрыв соединения (`socket.destroy()`) → `broken`/`CONNECTION`;
- недостижимый порт (закрытый) → `broken`/`CONNECTION`;
- дедупликация: один URL в 3 файлах → сервер получил 1 запрос (счётчик
  обращений на сервере);
- `--concurrency 1` и `--concurrency 8` дают одинаковый набор результатов;
- `--no-external`: HTTP не запрашивается вовсе (счётчик сервера = 0), ссылки
  `skipped`.

**Скипы и обход**
- `mailto:`, `tel:`, `data:` → `skipped`/`UNSUPPORTED_SCHEME`;
- `#anchor` → `skipped`/`ANCHOR_ONLY`;
- `node_modules`, `.git` не обходятся (создать в них `.md` со битой ссылкой —
  не должен появиться в отчёте);
- `--ignore custom` исключает каталог;
- `.markdown` подхватывается, `.txt`/`.mdx` — нет;
- пустая папка без `.md` → отчёт с нулями, exit `0`.

**CLI и вывод**
- без аргумента → exit `2`, usage в `stderr`;
- несуществующая папка → exit `2`;
- файл вместо папки → exit `2`;
- неизвестный флаг → exit `2`;
- `--timeout abc`, `--concurrency 0`, `--concurrency -1` → exit `2`;
- `--help`, `--version` → exit `0`;
- exit `0` на чистой фикстуре, exit `1` при наличии битой ссылки;
- `--json`: вывод парсится `JSON.parse`, содержит все ключи из §11, не
  содержит ANSI;
- `NO_COLOR=1` и не-TTY: в выводе нет `\x1b[`;
- при `--json` человекочитаемая таблица не печатается.

## 13. Критерии готовности

- [ ] `nvm use` даёт `node -v` = `v24.19.0`.
- [ ] `npm install` не создаёт зависимостей; `node_modules` отсутствует или пуст.

- [ ] Ни один тест не обращается к внешнему хосту.
- [ ] Все edge cases из §12 покрыты тестами.
- [ ] Коды выхода `0/1/2` соответствуют §3.
- [ ] README с примером запуска, флагами и известными ограничениями
      (регистр в путях, отсутствие проверки якорей, HTML-ссылки).

## 14. Вне объёма

Не реализовывать, даже если кажется полезным:

- Поиск «мёртвых»/orphan `.md` (файлов, на которые никто не ссылается).
- Проверка якорей/заголовков внутри файлов (`#section`).
- Ссылки в HTML-тегах (`<a href>`, `<img src>`).
- Прокси, авторизация, cookie, robots.txt.
- Кэш результатов между запусками, watch-режим.
- Автоисправление ссылок.
- Публикация в npm, CI-конфиги, Docker.
- TypeScript, сборка, линтеры.
